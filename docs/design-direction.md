# UI 디자인 방향 — 진행 기록 (2026-09-21)

새 세션에서 이 파일부터 읽고 이어갈 것. 관련: `README.md`, `docs/research-sources.md` §6-1(시제품 결과).

## 1. 사용자(제품 오너)의 지시

- UI 디자인이 큰 과제. https://motionsites.ai , https://www.originkit.dev , https://www.awwwards.com 과 여러 사이트·앱 사례를 참고해 제작.
- **검색·수집은 서브에이전트 여러 개(haiku/sonnet)에게 시키고, 메인 세션은 컨펌만** — 우리 프로젝트에 어울리는 요소와 디자인만 골라 진행.
- **무드**: 메인 화면에 뇌가 떠오르고, 배경은 약간 검은 **우주 느낌**. 사이트 전체의 테마는 **신비로움**.
- 직접 준 레퍼런스: https://mesh3d.gallery/the-state-of-the-gallery — "이런 배경이어도 멋있을 것 같다, 연출도."
  (Awwwards: https://www.awwwards.com/sites/the-state-of-the-gallery )
- "이런 요소들을 가져올 수 있는 MCP나 도구가 있으면 설치해서 해봐" → **Playwright MCP 설치함**(아래 §5).

작업 방식 주의(이 세션에서 도구 호출이 4번 거부됨): 질문에는 답부터, 맡긴 역할 밖의 실행은 하지 말 것.
메인 세션이 직접 긴 스크립트로 사이트를 긁으려던 시도도 거부됨 → 수집은 에이전트·MCP 도구로.

## 2. 컨셉 — "우주로서의 뇌"

신비로움은 **배경·빛·첫 등장**에 쓰고, **글자와 조작부는 또렷하게** 둔다. 장시간 공부하는 도구라는 점이 항상 우선.

넣을 것
- **배경**: 단색 검정이 아니라 푸른/보랏빛이 아주 살짝 도는 근흑색 + 방사형 비네트 + 옅은 성운 그라디언트 + 깊이감 있는 별(입자) 층. three.js 씬 안에서 셰이더/포인트로 구현(영상·이미지 에셋 없이).
- **첫 등장 연출**(2~3초, 첫 방문만, 클릭 시 건너뛰기): 검은 화면 → 입자가 모여 뇌 윤곽 형성 → 림라이트가 한 번 훑고 지나감 → 패널이 60~80ms 간격으로 순차 등장.
- **뇌**: 기존 고스트 셰이더(fresnel 림)가 이미 성운처럼 보임 → 림라이트 강화, 선택 구조에 옅은 bloom. 경로선은 "신호가 흐르는 빛줄기".
- **패널**: 전면 3D 위에 떠 있는 유리(글래스) 패널. Allen Brain Explorer식 "검은 전면 캔버스 + 떠 있는 패널"이 방향에 맞음. 경쟁작(nervous-system-atlas)의 3분할 개발자 도구형 레이아웃은 따르지 않음(차별점이 사라짐).
- **포인트 색**: 별빛/생물발광 계열 시안.

지킬 선
- 본문 대비비 WCAG AA(4.5:1) 이상을 **유리 패널 뒤로 밝은 구조가 지나갈 때도** 유지.
- 움직임은 첫 등장과 배경의 아주 느린 흐름에만. 공부 중 계속 번쩍이는 요소 금지. `prefers-reduced-motion`이면 전부 끔.
- 네온 그라디언트, 렌즈플레어, 스크롤 하이재킹, 거대한 히어로 타이포, 자동재생 영상 금지. SF 게임 UI처럼 보이면 실패.
- 남의 코드·셰이더·에셋·유료 템플릿을 복제하지 않는다. 가져오는 것은 기법과 수치.

### 3-1. 디자인 토큰 (채택안 — 대비비는 메인 세션이 직접 계산)

배경·표면
- `--bg-space: #060509` (처음엔 `#0a0912`였으나 사용자 요청으로 더 검게. 레퍼런스 mesh3d는 `#08090D`)
- `--surface: #1a1629` · `--surface-raised: #2a2340` · `--surface-overlay: #3a3250`
- 비네트 초안: `radial-gradient(ellipse at 50% 50%, rgba(10,9,18,0) 0%, rgba(30,15,45,.4) 70%, rgba(10,9,18,.8) 100%)`

글자 (괄호는 `--surface` 위 실제 대비비)
- primary `#f0f0f5` (15.5:1) · secondary `#b0b0c8` (8.3:1) · disabled `#6a6a85` (3.4:1)

포인트·의미 색
- accent 시안 `#a0e7ff` (12.9:1), 발광 `0 0 12px rgba(160,231,255,.6)`
  - 채택 이유: 현재 포인트 노랑 `#ffd34d`(hue 45°)는 **신경로의 노랑 `#e6d36a`(hue 51°)과 사실상 같은 색**이라 "선택됨"과 "신경로"가 충돌하고 있었음. 시안(hue 195°, 밝기 .81)은 시상 파랑 `#5b8def`(hue 220°, 밝기 .65)보다 훨씬 밝고 옅어 구분됨. **시상을 선택했을 때 헷갈리지 않는지 화면에서 확인할 것.**
- warning(초안 표시) `#d4a574` (7.9:1) — 빨강 대신 따뜻한 황갈색. 그 위 설명 글자로 제안된 `#a0826d`은 4.96:1이라 아슬아슬 → 더 밝게
- info `#87ceeb` · danger `#ff6b6b`(드물게)

유리 패널 — **제안값 수정 필요**
- 제안: `rgba(26,22,41,.72)` + `backdrop-filter: blur(16px)` + `1px solid rgba(255,255,255,.08)` + `inset 0 1px 2px rgba(255,255,255,.05)` + `0 8px 24px rgba(0,0,0,.48)`
- 실측: 어두운 배경 위에서는 primary 16:1로 좋지만, **패널 뒤로 밝은 구조가 지나가면 secondary 글자가 4.7:1(겉질 색 위) → 3.9:1(흰빛 위) → 3.3:1(순백)** 까지 떨어짐.
- 결정: 불투명도 **0.82~0.85**로 올리고 secondary 글자를 한 단계 밝게(`#c4c4d8` 안팎). 구현 후 대비비 재계산.
- 재계산(메인 세션, 패널 뒤 배경을 우주색 / 겉질색 가정 `#c9b8a8` / 순백으로 두고 합성):
  - 0.82 + `#c4c4d8`: 10.5 / 7.1 / **5.9** · 0.85 + `#c4c4d8`: 10.5 / 7.6 / **6.5** → 둘 다 AA 통과. primary는 최악의 경우에도 8.9 이상.
  - originkit 보고가 제안한 `rgba(16,20,27,.55)`: secondary 11.1 / 3.7 / **2.4**, primary도 순백 위 3.6 → **기각**.
- originkit에서 채택하는 것은 수치 두 가지뿐: `backdrop-filter`에 `saturate(180%)`를 더해 흐려진 3D가 탁한 회색이 되지 않게 하는 것(단 `brightness()` 증폭은 대비를 깎으므로 넣지 않음), 패널 테두리 1px 흰색 8~10%(`#FFFFFF14`~`#FFFFFF1A`). 마우스를 따라다니는 하이라이트는 넣지 않음.

타이포(한글)
- Pretendard(OFL) 본문·UI. 본문 최소 14px, 줄간격 1.6(한글은 라틴보다 +0.2). 라벨 12px/500/+0.25px.
- 숫자·좌표는 tabular-nums. 고정폭이 필요하면 D2Coding(OFL).
- 영문 디스플레이 서체(Space Grotesk 제안)는 보류 — 한글이 없어 효과가 제한적.

간격·모서리·모션
- 간격 4/8/16/24/32/48 · 모서리 4/8/12/16
- 표준 200ms, 패널 등장 400ms, 3D 조작은 즉시. easing `cubic-bezier(0.2, 0.85, 0.32, 1)`; 탭·세그먼트는 150ms `cubic-bezier(0.4,0,0.2,1)`

### 3-2. 채택한 UI 요소

- 단계 목록의 완료/현재/예정 3상태(현재 = 좌측 2px 포인트 테두리 + 옅은 발광)
- "초안·검수 전" 표시는 따뜻한 황갈색 좌측 테두리 콜아웃(놀라게 하지 않기)
- 구조 트리: 색 견본 + 그룹별 개수 + 3상태 그룹 체크박스(경쟁작에서 확인한 관례)
- 호버(임시 라벨) vs 선택(패널 고정) 구분 — 이미 있음, 시각적으로 더 분명히
- "기본값으로" 복구 버튼, 방향 표시 위젯(뷰 큐브/축), 단축키 도움말(?)
- 메시 로딩 중 스켈레톤 시머(`1.6s ease infinite` 그라디언트 스윕 → 300ms 크로스페이드)
- `mask-composite: exclude`로 만드는 1px 그라디언트 테두리 배지
- 제목의 은은한 발광: 같은 글자를 두 겹으로, 한 겹은 `blur(10px)` + `mix-blend-mode: screen`
- 패널 섹션의 60~80ms 간격 순차 등장
- (originkit 앱 크롬 실측, 스크린샷 `11-sidebar-crop.png`·`12-property-panel-crop.png`과 대조함)
  - 좌/우 기시측 전환 = 세그먼트 컨트롤: 트랙 높이 36px·모서리 10px·안쪽 여백 2px, 활성 표시는 별도의 미끄러지는 알약(모서리 8px), `220ms cubic-bezier(0.16, 1, 0.3, 1)`. 활성 알약은 회색 대신 1px 시안 테두리 + 옅은 발광.
  - 단면 높이 슬라이더: 36px 높이 트랙 + `scaleX`로 채우는 막대 + 둥근 손잡이 대신 **폭 10px 세로 막대 손잡이**(계기판 느낌). 손잡이만 포인트 색.
  - 구조 트리 그룹 개수 배지: 12px 글자, 모서리 10px, 여백 4×6px, 칩보다 한 단계 밝은 면 + 1px 테두리.
  - 목록 호버: 흰색 3% 면 + 글자색만 밝아짐(테두리·배경색 변화 없음).
  - 쉬는 상태의 헤어라인 테두리 흰색 4%(`#FFFFFF0A`) ↔ 포커스/활성 시 포인트 색 테두리 + `0 0 12px` 발광, 150~200ms 1회 전환. **테두리를 계속 도는 빛은 금지.**
  - 포커스 링은 1px. 흰색 40% 대신 포인트 시안.
  - 토글의 켜짐 상태는 흑백 반전 대신 포인트 색 저알파 트랙 + 손잡이 발광("켜짐 = 불이 들어옴").
- **반면교사**: motionsites의 카드 펼침은 애니메이션 없는 즉시 교체 — 우리는 카메라 이동 + 패널 교체가 핵심 상호작용이므로 이 전환을 제대로 만든다

### 3-3. 기각·보류

- 60/40 고정 분할, 3분할 개발자 도구형 레이아웃(경쟁작과 같아짐)
- 하단에 단면 3개를 나란히 두는 배치(3D를 가림) — 우리는 떠 있는 패널 하나로 유지
- 빨간 십자선 등 의료영상 관례를 그대로 들이는 것(무드와 충돌; 단면 패널 안에서만 절제해서)
- 유료 스톡 배경 영상, AI 생성 목업 자산
- 단축키 힌트가 줄마다 붙는 조밀한 목록(나중에 검토)

### 3-4. Awwwards 조사에서 채택한 것 (스크린샷: `data/design-refs/awwwards/_s-*.png`)

- **Everest · The Ascent — 첫 등장(로딩) 화면의 틀**: 남색빛 근흑색 + 방사형 비네트 → 작은 별 하나 → 얇은 세리프 제목 → 1px 진행 막대 → 대문자·넓은 자간의 상태 문구("LIGHTING THE RANGE · 47%"). 메시 4MB를 받는 동안 같은 구성을 쓴다(우리 말로: "신경로를 밝히는 중 · 47%"). 조용하고 짧게 — 스펙터클이 아님.
- **Whiteout · An Ascent — 입자의 깊이와 정보 배치**: 가까운 입자는 크고 흐릿하게, 먼 입자는 작고 또렷하게(크기·선명도·밝기 3중 차이) → 별먼지 층의 기준. 좌상단 큰 고정폭 숫자 + 작은 단위 라벨, 우측의 눈금 달린 얇은 세로 진행 레일 → 단면 높이 `z = −46.2 mm` 표시와 경로 단계 레일에 대응. 서체 짝: Archivo(UI) + JetBrains Mono(숫자), 둘 다 OFL — 에이전트 보고, 라이선스는 도입 시 재확인. 한글은 Pretendard 유지, 숫자·좌표에만 JetBrains Mono 검토.
- **21 Hrs on the Moon — 3D에 붙은 라벨과 챕터 레일**: 3D 표면의 지점에 아이콘 배지 + 대문자 소형 라벨, 하단 가로 챕터 레일(눈금 + 현재 위치 표시), 화면 모서리 브래킷 프레임 → 구조 콜아웃(활성 구조 옆에 이름 라벨)과 단계 레일.
- **Orchid Security — 유리 카드**(에이전트 보고, 메인 세션 미확인): `backdrop-filter: blur(100px)`, `1px solid rgba(255,255,255,.1)`, 투명 채움. 채움 없는 유리는 우리 대비비 기준(§3-1)을 못 맞추므로 **테두리 값만** 참고.
- **SentientX — 절제의 기준**: 가는 선 몇 개뿐인 궤도 고리. 싸구려 SF처럼 보이지 않으려면 이 정도로 덜어낸다.
- 공통 패턴(에이전트 종합): 색조가 살짝 도는 근흑색 배경, 포인트 색은 하나만 아껴서, 고정폭 서체는 숫자에만, 조용한 단계 레일, 짧고 차분한 등장 연출.

기각
- 21 Hrs의 "MOON" 도입부 같은 스크롤 가로채기 인트로, "BASE CAMP"급 거대 타이포, 본문 옆 문학적 카피.

## 4. 레퍼런스: mesh3d "The State of the Gallery"

Awwwards 공식 정보로 확인한 것: 제작 Majo Puterka, 2026-08-22 Site of the Day, 애니메이션/트랜지션 8.4/10, **Three.js + WebGL + React**, 스크롤 기반 단일 페이지, 대표 색 `#08090D`. mesh3d.gallery 자체가 Three.js 작업물 큐레이션 갤러리라 추가 레퍼런스 탐색처로도 유용.

**관찰 완료(2026-09-21 오후, sonnet 에이전트 + Playwright MCP, 실제 GPU 렌더).** 보고서: `data/design-refs/mesh3d/REPORT.md`, 화면: `01-load-early.png`·`02-idle-a.png`·`03-idle-b.png`·`04-scrolled.png`(메인 세션이 첫 장을 보고서와 대조함. 끊기기 전에 찍은 5장은 재개 후 이 4장으로 다시 찍어 교체됨).

실측으로 확인된 것
- **배경은 파랑·보라가 아니라 올리브/연두빛 성운 물결** + 흰색~연노랑 입자(별·먼지) + 근흑색 `#08090D`. 사용자가 좋다고 한 것은 색조가 아니라 "어둠 속에서 빛나는 안개 물결 위로 입자가 깊이감 있게 떠 있는" 구성으로 해석 → 우리는 같은 구성을 §3-1의 푸른/보랏빛 토큰으로 만든다(**색조는 사용자 확인 필요**).
- CSS 비네트·그라디언트 오버레이는 **없음**(전면 div 3개 모두 투명). 깊이감·성운·입자는 전부 WebGL 캔버스 안에서 그림. 캔버스는 1개, `alpha:true`로 CSS 배경색 위에 얹음. 텍스처·HDR·모델 요청 없음 → 절차적 셰이더 + GPU 입자로 추정.
- 가만히 있어도 배경이 계속 천천히 흐름(몇 초 간격 두 장 비교: 픽셀의 18.9%가 10단계 이상 변함).
- 로딩 화면·진행률 요소 없음. 제목은 글자 단위 span, `transform/opacity 0.7s cubic-bezier(0.22, 1, 0.36, 1)`, 등장 전 상태는 아래로 ~127px 내려가 있고 투명. **등장 연출의 초 단위 순서는 못 잡음**(MCP 호출 지연 ~4초, `preserveDrawingBuffer:false`라 캔버스 캡처 불가) — 4초 안에 끝난다는 상한만 확인.
- 스크롤은 완전 가로채기(`overflow:hidden`, 스크롤 높이 = 화면 높이). 휠 입력 → 입자 속으로 "뛰어드는" 카메라 이동, 안내 문구가 "SCROLL TO DIVE IN" → "KEEP GOING"으로 바뀜.
- 글자: 자체 호스팅 서체(라이선스 미확인 → 쓰지 않음). 제목 115px/400/자간 −1%, 소형 라벨 14px/대문자/자간 +2%/`#CFDEE5`(배경 대비 14.4:1).
- 가장자리 입자에 빨강/청록 번짐 = 색수차 후처리(스크린샷에서도 보임, 추정).

보고서에서 바로잡은 것
- 제목 색을 `#FFFFFF`로 실측했다고 했으나 화면에서는 연한 청회색 → 라벤더로 변하는 그라디언트로 보임(블렌드/마스크일 가능성). 수치로 쓰지 않음.
- "3D 오브젝트의 빛 처리"는 해당 없음 — 이 페이지에는 조명받는 메시가 없고 입자·성운 자체가 주인공. 뇌의 림라이트/bloom 기준은 Awwwards 조사(§3-4)에서 찾아야 함.

채택
- CSS `body` 배경색 + `alpha:true` 투명 캔버스(씬을 불투명 색으로 지우지 않음). DOM 비네트 레이어는 두지 않고 셰이더 안에서 처리(§2의 계획과 일치, §3-1의 CSS 비네트 초안은 셰이더로 옮김).
- 성운 = 노이즈 기반 셰이더 물결, 별 = 포인트 입자 2~3겹(깊이별 크기·밝기 차), 아주 느린 `uTime` 드리프트. 텍스처 에셋 없이.
- 등장 easing `cubic-bezier(0.22, 1, 0.36, 1)` 0.7s — 패널 순차 등장(60~80ms 간격)에 사용.
- 진행 상태에 따라 바뀌는 안내 문구("구조를 클릭해 보세요" → "경로 재생 중").
- "뛰어드는" 카메라 이동은 **첫 등장 연출 1회**와 경로 선택 시의 카메라 전환에만 차용.

기각
- 색수차·RGB 번짐 후처리(게임/시네마 UI 느낌 — §2의 실패 기준).
- 115px 히어로 타이포, 오디오 토글, 한 화면 한 메시지식 진행.
- 스크롤 가로채기를 패널·목록에 적용하는 것(3D 무대에서만 휠 = 줌, 목록은 기본 스크롤).
- 공부 중에도 전면 배경이 큰 진폭으로 계속 움직이는 것 → 진폭을 크게 낮추고, `prefers-reduced-motion`이면 정지, **카메라·씬이 멈춰 있으면 렌더 루프를 저프레임(또는 정지)으로 낮추는 방안 검토**(58만 면 메인 패스를 매 프레임 다시 그리는 비용이 실제 위험. 전면 후처리 패스를 얹기 전 프레임 예산 측정 필수).

검증 (직접 실행)
- 실제 GPU(M5 Pro, 1500×900)에서 **60fps 유지**(vsync 상한), draw 109~114. 입력이 3초 없으면 렌더를 격프레임으로 낮춤.
- 단위·e2e 전부 통과(pytest 12, vitest 8, Playwright 6 — e2e는 `reducedMotion: 'reduce'`로 돌려 결정적).
- **대비비(최종 토큰, 유리 0.84)** — 패널 뒤가 우주색 / 겉질색 / 고스트 림색 / 순백일 때: 본문 15.9 / 11.5 / 10.2 / 9.5, 보조 10.5 / 7.6 / 6.8 / 6.3, 포인트 13.2 / 9.6 / 8.5 / 7.9. 가장 옅은 글자는 `#8d8da8`이 3.4~4.1로 미달이라 **`#adadc6`으로 올림** → 8.2 / 6.0 / 5.3 / 4.9.
- 구현 중 잡은 버그: (1) 불투명 `MeshStandardMaterial`은 `OPAQUE` 정의로 컴파일돼 `opacity`를 무시 → 처음부터 `transparent`로 만들고 등장 후 되돌리며 `needsUpdate`. (2) 커스텀 셰이더에 `<colorspace_fragment>`를 빼먹어 성운이 의도보다 훨씬 어둡게 나옴.

사용자 피드백 반영 (같은 날): "첫 화면은 좋다. 띄워진 화면에서는 별을 없애고 배경을 더 검게."
- 별·먼지와 밝은 성운은 **등장 연출 동안만**. 연출 끝(2.5~3.4s)에 별이 꺼지고 성운이 `SETTLED_NEBULA = 0.22`로 가라앉음. 재방문(짧은 페이드)과 reduced-motion에서는 처음부터 별 없이 가라앉은 상태. 별 레이어는 밝기 0이면 아예 그리지 않음(draw call 3개 절약).
- 바탕색 `#0a0912` → **`#060509`** (CSS `--bg-space`, 렌더러 클리어 색, 성운 셰이더의 `uBase`, theme-color). 글자 대비비는 배경이 더 어두워진 만큼 같거나 높아짐.

사용자 피드백 2 (같은 날): "레퍼런스처럼 빈 공간을 클릭하면 계속 물결치게. 검지 않아도 되고 색도 레퍼런스 같은 색이어도 된다. (2) 시뮬레이션 방식으로, 절제는 인정."
- **파동 시뮬레이션** `src/scene/WaveField.ts`: three.js에 들어 있는 `GPUComputationRenderer`(MIT, 새 의존성 없음)로 화면 공간 높이장을 GPU에서 스텝. 텍셀마다 (높이, 이전 높이)를 두고 `다음 = (상+하+좌+우)/2 − 이전`에 감쇠 0.986을 곱하는 고전적 2-버퍼 방식 → 물결이 서로 부딪히고 간섭하며 남았다가 사라짐. 200행 × 화면비(정사각 텍셀 → 원형 파동), half-float + 선형 필터(WebGL2 기본 기능만 사용), 가장자리는 흡수 경계. 초당 60스텝 → 화면 절반을 약 2.3초에 가로지름.
- 성운 셰이더가 높이장을 읽어 (a) 기울기만큼 안개 조회 방향을 굽히고(물 너머로 보는 굴절), (b) 높이와 기울기를 합친 **포락선**으로 빛을 더함 — 높이나 기울기 하나만 쓰면 한 파장에 두 번 어두워져 "과녁 고리"가 되는데(처음 구현이 그랬음), 둘은 1/4 파장 어긋나 있어 합치면 부드러운 빛의 띠가 됨.
