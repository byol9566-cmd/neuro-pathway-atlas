# 데이터 형식 안내 (성연에게)

이 폴더의 `pathways.json`, `structures.json`은 **지금 뷰어가 실제로 읽고 있는 파일 그대로**야.
VOR·파페츠·DCML 세 경로가 어떻게 저장돼 있는지 열어 보고, 같은 모양으로 보내 주면 바로 들어가.

- 형식은 JSON. 메모장·VS Code 아무 걸로나 열림. 괄호·쉼표가 헷갈리면 `검수시트/`의 CSV로 줘도 똑같이 받을 수 있어(열 이름이 아래 항목과 1:1).
- 완벽하게 맞출 필요 없음. 모르는 칸은 비우거나 `"?"`, 하고 싶은 말은 `"memo"`에 자유롭게. 형식 오류는 내가 고쳐.


## 1. 신경 작용(경로) 하나의 형식 — `pathways.json`

실제 저장된 VOR을 줄여서 보면:

```json
{
  "id": "hvor",
  "category": "oculomotor",
  "name":    { "ko": "수평 안뜰눈반사 (VOR)", "en": "Horizontal vestibulo-ocular reflex" },
  "summary": { "ko": "머리가 한쪽으로 돌 때 두 눈을 반대 방향으로 … 묶는다." },
  "origin":  { "ko": "머리가 도는 쪽" },
  "defaultOriginSide": "L",
  "reviewStatus": "draft",

  "steps": [
    {
      "id": "hvor-1",
      "neuronOrder": 1,
      "title":       { "ko": "수평반고리관 → 안쪽안뜰핵" },
      "description": { "ko": "머리가 도는 쪽의 수평반고리관이 흥분하고 … 시냅스한다." },
      "structures":  [ { "id": "bs-vestibular-medial", "side": "ipsi" } ],
      "missing":     { "ko": "속귀·안뜰신경은 시제품 데이터에 없음" }
    },
    {
      "id": "hvor-2",
      "neuronOrder": 2,
      "title":       { "ko": "반대쪽 갓돌림신경핵" },
      "description": { "ko": "안뜰핵 뉴런(2차)이 정중선을 건너 … 수축시킨다." },
      "decussation": true,
      "structures":  [ { "id": "bs-abducens", "side": "contra" } ]
    }
  ],

  "lesions": [
    { "level":   { "ko": "안쪽세로다발 (MLF)" },
      "deficit": { "ko": "핵사이눈근육마비(INO): 병변쪽 눈의 모음 장애 + …" } }
  ]
}
```

### 경로 항목

| 키 | 꼭? | 뜻 |
|---|---|---|
| `id` | ○ | 영문 소문자·하이픈. 예: `pupillary-light-reflex` |
| `category` | ○ | 분류. 지금 쓰는 값: `somatosensory`, `limbic`, `oculomotor`. 새로 만들어도 됨(`motor`, `reflex`, `visual`, `auditory`, `autonomic`, `cerebellar`, `basal-ganglia`, `arousal`, `pain` …) |
| `name.ko` / `name.en` | ○ | 이름 |
| `summary.ko` | ○ | 한두 문장 요약 |
| `origin.ko` | ○ | **좌우의 기준이 되는 쪽을 부르는 말.** 뷰어의 좌/우 스위치 옆에 붙어. 예: "자극을 받는 몸 쪽", "머리가 도는 쪽", "빛을 비춘 눈" |
| `defaultOriginSide` | ○ | 처음 열었을 때 기준쪽: `"L"` 또는 `"R"` |
| `reviewStatus` |  | 네가 확인한 경로는 `"reviewed"`, 아니면 `"draft"` |
| `steps` | ○ | 단계 목록(아래) — **순서대로** |
| `lesions` |  | 병변 → 증상 목록(아래) |

### 단계(`steps`의 한 칸)

| 키 | 꼭? | 뜻 |
|---|---|---|
| `id` | ○ | `경로id-번호`. 예: `hvor-3` |
| `title.ko` | ○ | 단계 제목 (짧게) |
| `description.ko` | ○ | 2~3문장 설명 |
| `structures` | ○ | **이 단계에서 밝게 표시할 구조들.** 각각 `{ "id": 구조id, "side": "ipsi" 또는 "contra" }`. 3D에 없는 구조뿐이면 빈 목록 `[]` |
| `neuronOrder` |  | 1·2·3차 뉴런. 해당 없으면 생략 |
| `decussation` |  | 이 단계에서 정중선을 건너면 `true` |
| `missing.ko` |  | 설명에는 나오지만 3D에 아직 없는 구조(예: 속활꼴섬유, 속섬유막). **지우지 말고 여기 적어 줘 — 다음에 뭘 3D로 만들지 정하는 목록이 돼** |

> **가장 중요한 규칙 — `side`는 왼쪽/오른쪽이 아니라 기준쪽(`origin`) 대비야.**
> `ipsi` = 기준쪽과 같은쪽, `contra` = 반대쪽. 뷰어에서 좌/우 스위치를 누르면 전체가 뒤집혀.
> 예) DCML, 기준 = 자극받는 몸 쪽: 널판핵 `ipsi` → 안쪽섬유띠 `contra` → VPL `contra` → 중심뒤이랑 `contra`.
> 예) VOR, 기준 = 머리가 도는 쪽: 안쪽안뜰핵 `ipsi` → 갓돌림신경핵 `contra` → MLF `ipsi` → 눈돌림신경핵 `ipsi`.

아직 저장 형식에 없지만 **네가 넣어 주면 받아서 반영할 칸** (단계에 자유롭게 추가):

```json
"decussationSite": { "ko": "숨뇌 아래쪽 (감각교차)" },
"transmitter": "glutamate",
"source": "Blumenfeld 3판 p.279",
"memo": "학교에서는 '내측섬유띠'라고 부름"
```

양쪽 다 표시해야 하는 단계(예: 동공빛반사의 양쪽 EW핵)는 같은 구조를 두 번 적으면 돼:
`"structures": [ { "id": "bs-ew", "side": "ipsi" }, { "id": "bs-ew", "side": "contra" } ]`

### 병변(`lesions`의 한 칸)

| 키 | 꼭? | 뜻 |
|---|---|---|
| `level.ko` | ○ | 병변 위치 |
| `deficit.ko` | ○ | 증상 |
| `side` |  | 증상이 병변의 `ipsi` / `contra` / `bilateral` (추가해 주면 반영) |
| `syndrome` |  | 관련 증후군 이름 (추가해 주면 반영) |


## 2. 뇌 구성 핵/신경로 세트의 형식 — `structures.json`

실제 저장된 모습:

```json
{ "id": "thal-vpl", "group": "thalamus",
  "name": { "ko": "배쪽뒤가쪽핵 (VPL)", "en": "Ventral posterolateral nucleus" },
  "source": { "atlas": "nextbrain", "labels": [394, 458] } },

{ "id": "tr-mlf", "group": "tracts", "tract": true,
  "name": { "ko": "안쪽세로다발 (MLF)", "en": "Medial longitudinal fasciculus" },
  "source": { "atlas": "nextbrain", "labels": [528] } },

{ "id": "bs-oculomotor", "group": "brainstem-nuclei",
  "name": { "ko": "눈돌림신경핵 (III)", "en": "Oculomotor nucleus" },
  "source": { "atlas": "nextbrain", "labels": [464], "placeholder": { "radiiMm": [1.4, 2.6, 2.2] } } }
```

| 키 | 꼭? | 뜻 |
|---|---|---|
| `id` | ○ | 영문 소문자·하이픈. 앞머리 관례: `thal-`(시상) `bg-`(바닥핵) `bs-`(뇌줄기 핵) `tr-`(신경로) `lim-`(둘레계통) `ctx-`(겉질) `cb-`(소뇌) `hyp-`(시상하부) |
| `group` | ○ | `cortex` `thalamus` `basal-ganglia` `limbic` `brainstem-nuclei` `tracts` `cerebellum` 중 하나 (새 그룹이 필요하면 말해 줘) |
| `name.ko` / `name.en` | ○ | 학교에서 쓰는 용어로. 옛 용어는 괄호나 `memo`에 |
| `source.labels` | ○ | **이 구조를 이루는 아틀라스 라벨 번호들. 여러 개를 적으면 하나로 합쳐짐 = 네가 말한 "적절하게 묶기".** 번호와 이름은 `검수시트/5_참고_Allen라벨.csv`에 333개 전부 있어(Allen Human Brain Atlas의 구조명과 같음) |
| `tract` |  | 신경로면 `true` (경로선이 구조의 중심선을 따라가게 됨) |
| `centerline` |  | 신경로는 아니지만 길쭉하게 휜 구조(해마, 띠이랑)면 `true` |
| `source.placeholder.radiiMm` |  | 라벨이 너무 작아 타원체로 대신할 때의 반지름 [좌우, 앞뒤, 위아래] mm. 크기를 아는 핵이 있으면 알려 줘 |

**라벨 번호를 몰라도 돼.** 번호 대신 이름으로 줘도 내가 변환해:

```json
{ "id": "thal-md", "group": "thalamus",
  "name": { "ko": "등쪽안쪽핵 (MD)", "en": "Mediodorsal nucleus" },
  "allen": ["magnocellular (medial) division of MD", "parvocellular (central) division of MD",
            "densocellular (paralamellar) division of MD", "multiform (lateral) division of MD"] }
```

아틀라스에 아예 없는 구조(예: 속섬유막, 척수의 구조, 렌즈핵고리)는 `labels` 없이 이름만 적고
`"memo": "아틀라스에 없음"`이라고 해 줘. 직접 모델링할 후보 목록으로 모아 둘게.

### 크기 참고 (5_참고_Allen라벨.csv의 '크기_판정')
- **메시 가능** (20 mm³ 이상): 바로 3D로 나옴
- **작음** (5~20): 나오긴 하는데 실제보다 작을 수 있음
- **극소** (5 미만): 위치만 쓰고 모양은 타원체로 대신함 — 눈돌림·도르래신경핵, 의문핵, 고립로핵, 미주신경등쪽핵 등이 여기 해당


## 3. 보내는 방법

- 경로는 `pathways.json`에 항목을 이어 붙이거나, 경로 하나당 파일 하나(`pupillary-light-reflex.json`)로 줘도 돼.
- 구조는 `structures.json`의 `structures` 목록에 이어 붙이면 돼.
- 단계에서 쓰는 구조 `id`가 구조 목록에 있어야 해. 없는 걸 쓰면 내 쪽 검사에서 걸러지니까 걱정 말고 일단 적어.
- 지금 들어 있는 세 경로의 설명과 한국어 용어는 **AI가 쓴 초안**이야. 틀린 데가 있으면 그 자리에서 고쳐서 보내 줘.
