# 세로·가로 단면 기반 3D 모델링 도구 조사 및 Claude 인계

- 정리일: 2026-10-04
- 사용자 요청: “세로 단면과 가로 단면 데이터를 가지고 3D 모델링을 하는 데에 도움이 될 만한 도구나 오픈소스를 찾아봐.”
- 조사 범위: 공식 문서, 프로젝트 저장소, 관련 연구의 입력 조건과 기능 비교
- 검증 수준: 문서 및 저장소 확인. 설치, 샘플 실행, 실제 데이터 복원은 수행하지 않음.

## 1. 핵심 판단

입력이 단면 **윤곽 곡선**인지, 단면 **이미지**인지에 따라 접근 방법이 달라진다.

- 가로·세로 윤곽 곡선을 함께 반영한 CAD 곡면: **FreeCAD + Curves Workbench** 또는 **Rhino**.
- 연속 단면 이미지나 영역 마스크의 보간 및 3D 복원: **3D Slicer**.
- 여러 방향의 평면 단면에서 형상을 자동 추정하는 연구·개발: **OReX**.
- 지층 경계 및 방향 데이터로 지질 모델 생성: **GemPy**.

현재 데이터 형식과 대상이 확인되지 않았으므로 최종 도구는 아직 선정하지 않았다. FreeCAD의 Gordon Surface를 첫 검토 대상으로 제안한 것은 두 방향의 윤곽 곡선이 있다는 조건에 따른 판단이다.

## 2. 아직 확인되지 않은 입력 조건

다음 항목을 먼저 확인해야 한다.

1. 대상: 부품, 제품 외형, 건축물, 지형·지층, 인체·해부 구조 등.
2. 파일 형식: DXF·SVG 등 곡선, PNG·JPG 등 이미지, DICOM 등 볼륨, CSV·XYZ 등 좌표.
3. 단면 수: 가로·세로 각각 한 장인지, 여러 위치에 걸친 단면 묶음인지.
4. 공간 정보: 각 단면의 위치, 방향, 간격, 좌표계, 실제 단위가 있는지.
5. 표현 의미: 실제 절단면인지, 정면·측면 투영도나 외곽 실루엣인지.
6. 출력 목적: 시각화용 메시, 3D 프린팅용 폐곡면, 편집 가능한 CAD 솔리드 등.
7. 정확도와 자동화 수준: 시각적 근사인지, 치수 정확도가 필요한지, 반복 처리가 필요한지.

세로 한 장과 가로 한 장만으로는 일반적으로 3D 형상이 유일하게 결정되지 않는다. 단면 사이 형상을 정하려면 추가 단면, 대칭성, 매끄러움, 두께 등의 조건이 필요하다. 실제 절단면과 투영도도 같은 입력으로 취급해서는 안 된다.

## 4. 후보별 상세와 출처

### 4.1 FreeCAD + Curves Workbench

Gordon Surface는 두 방향의 곡선망을 바탕으로 곡면을 만든다. 가로 단면의 윤곽을 한 방향 곡선으로, 세로 단면의 윤곽을 다른 방향 곡선으로 활용하는 접근에 직접적으로 연결된다.

- 서로 다른 그룹의 곡선들이 교차하는 망 구조가 필요하다.
- 전체 닫힌 윤곽을 한 번에 처리하기 어려운 형상은 곡면 패치로 나누는 접근을 검토한다.
- 생성된 곡면과 닫힌 솔리드는 구분해야 한다. 입체화에는 추가 경계면 구성과 연결 검사가 필요할 수 있다.
- FreeCAD Addon Manager에서 Curves 확장을 설치할 수 있다.
- 개발자는 확장을 실험적이며 초보자에게 적합하지 않다고 명시한다. 생산 작업 채택 전 실제 데이터로 검증해야 한다.

출처:

- [Gordon Surface 공식 문서 저장소](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Curves_GordonSurface.md)
- [Curves Workbench 코드 및 설치 안내](https://github.com/tomate44/CurvesWB)
- [FreeCAD Part Loft 문서](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Part_Loft.md)

### 4.2 Rhino

NetworkSrf는 교차 곡선망으로 곡면을 생성한다. 가로·세로 곡선을 모두 반영하고 경계 및 내부 곡선에 대한 허용 오차를 설정할 수 있다.

- 한 방향의 모든 곡선이 다른 방향의 모든 곡선과 교차해야 한다.
- 같은 방향 그룹 안의 곡선끼리는 교차하면 안 된다.
- 입력에 꺾임이 있어도 출력 곡면을 매끄럽게 만드는 특성이 있으므로 모서리 보존 요구를 확인해야 한다.
- 유료 도구를 사용할 수 있는 경우 비교 후보로 적합하다. 가격·구매 조건은 이번 조사에서 비교하지 않았다.

출처: [Rhino 8 NetworkSrf 공식 문서](https://docs.mcneel.com/rhino/8/help/en-us/commands/networksrf.htm)

### 4.3 3D Slicer

단면 이미지에서 관심 영역을 분할하고 3D 표면으로 변환하는 작업에 적합하다. Fill between slices는 일부 단면에 지정한 영역을 이용해 중간 단면을 보간한다.

- 보간 기능은 원본 영상의 밝기보다 지정된 영역의 형상을 사용한다.
- 임의 방향 단면에서 편집할 수 있다는 사실과, 희소한 직교 단면들을 자동 결합해 복원할 수 있다는 주장은 구분해야 한다.
- 현재 입력이 서로 직교하는 소수의 이미지라면, 해당 배치에서 가능한 보간 절차를 샘플로 확인해야 한다.
- 이미지 정렬과 공간 정보 설정을 생략할 수 없다.

출처:

- [3D Slicer 소개 및 오픈소스 안내](https://www.slicer.org/)
- [Segment Editor 및 Fill between slices](https://slicer.readthedocs.io/en/latest/user_guide/modules/segmenteditor.html)
- [Segmentations와 데이터 표현 변환](https://slicer.readthedocs.io/en/5.8/user_guide/modules/segmentations.html)
- [공식 코드](https://github.com/Slicer/Slicer)

### 4.4 OReX

논문 제목은 “Object Reconstruction from Planar Cross-sections Using Neural Fields”이며 공식 PyTorch 구현이 공개되어 있다. 평면 단면에서 3D 형상을 추정하는 개발용 후보로 검토할 수 있다.

README의 입력 형식은 `.csl`이며 다음 정보가 포함된다.

- 단면 평면 수와 영역 라벨.
- 각 평면의 방정식 계수: `Ax + By + Cz + D = 0`.
- 해당 평면 위 윤곽점의 3D 좌표.
- 윤곽점을 연결하는 순서, 연결 성분, 구멍 정보.

따라서 PNG나 DXF를 그대로 넣는 방식이 아니라 전처리와 형식 변환이 필요하다. README의 실행 예시는 CUDA 장치 지정을 포함한다. GPU 요건 및 현재 라이브러리 호환성은 실행 검증이 필요하다. 코드 공개와 재사용 허용 범위는 별개이므로 제품에 통합하기 전 라이선스를 확인해야 한다.

출처:

- [공식 코드와 .csl 규격](https://github.com/haimsaw/OReX)
- [논문](https://arxiv.org/abs/2211.12886)

### 4.5 GemPy

지층 경계점과 방향 정보를 이용하는 3D 지질 모델링 라이브러리다. 단면이 지질도·지층도라면 일반 CAD보다 먼저 검토할 수 있다.

- 단면 이미지 자체보다 지층 경계의 XYZ 좌표와 방향 정보가 입력의 중심이다.
- 공식 예제에는 경계점 CSV와 방향 CSV를 읽어 모델을 생성하는 흐름이 있다.
- 지표면만 생성하려는 경우와 지층 내부 구조까지 모델링하려는 경우를 구분해야 한다.

출처:

- [공식 코드](https://github.com/gempy-project/gempy)
- [CSV 입력 기반 모델링 예제](https://docs.gempy.org/tutorials/a_getting_started/video_tutorial_model_1.html)

## 5. 관련 연구: CrossSDF

“CrossSDF: 3D Reconstruction of Thin Structures From Cross-Sections”는 얇거나 가지가 갈라지는 구조의 단면 기반 복원과 관련된 연구다.

다만 이번에 확인한 공식 저장소는 README에서 평가용 데이터셋을 제공하는 저장소라고 설명하고 있으며, 파일 목록도 데이터·프로젝트 페이지 중심이었다. 따라서 즉시 실행할 수 있는 복원 구현이 확인된 OReX와 동일하게 취급하지 않았다.

## 6. 조건별 권장 선택

| 확인된 상황 | 먼저 검토할 후보 |
|---|---|
| 두 방향의 윤곽 곡선이 있고 오픈소스 CAD가 필요함 | FreeCAD + Curves Workbench의 Gordon Surface |
| 교차 곡선 기반 자유곡면 작업이며 상용 도구 사용 가능 | Rhino NetworkSrf |
| 같은 방향의 단면이 여러 위치에 순서대로 있음 | FreeCAD Part Loft |
| 이미지 스택 또는 공간 정보가 있는 영역 마스크가 있음 | 3D Slicer |
| 희소한 여러 방향 단면에서 자동 복원 알고리즘을 개발하려 함 | OReX |
| 지층 단면 및 지질 경계·방향 데이터가 있음 | GemPy |

이는 문서 기능에 따른 추천이며, 실제 데이터의 복원 품질이나 처리 속도를 비교한 벤치마크 결과는 아니다.

## 7. 권장 검증 절차

1. 대표 단면 몇 개로 작은 샘플을 선정한다.
2. 단면의 단위, 위치, 방향을 공통 3D 좌표계로 정렬한다.
3. 이미지라면 윤곽 또는 영역 마스크를 추출한다.
4. 단면들이 만나는 위치에서 윤곽이 일치하는지 확인한다.
5. 후보 하나로 곡면 또는 메시를 생성한다.
6. 결과를 원본 단면 위치에서 다시 잘라 입력 윤곽과 비교한다.
7. 치수 오차, 구멍·분기 보존, 자기 교차, 폐곡면 여부를 목적에 맞게 확인한다.
8. 성공한 흐름에 한해 전체 데이터 처리와 자동화를 진행한다.

개념적인 처리 흐름:

```text
단면 데이터
  → 좌표·단위·위치 정렬
  → 윤곽/영역 추출
  → Loft / 곡선망 곡면 / 영역 보간 / 신경망 복원
  → 곡면·메시 생성 및 필요한 입체화
  → 원본 단면과 재비교
```

## 8. Claude에게 전달할 작업 지시

다음 요청으로 이어서 진행할 수 있다.

> 이 문서는 세로·가로 단면 데이터에서 3D 모델을 생성하기 위한 도구 조사 결과다. 아직 실제 입력 데이터 형식과 대상은 확정되지 않았다. 먼저 제공된 프로젝트 자료와 샘플에서 대상, 파일 형식, 단면 수, 공간 좌표·단위, 최종 출력 목적을 확인하라. 확인되지 않은 조건을 임의로 확정하지 말고 필요한 질문만 하라. 그다음 문서의 후보 중 1~2개를 선정하고, 작은 샘플로 검증 가능한 구현 절차를 제안하라. 실제 단면과 투영도를 구분하고, 복원 결과를 같은 평면에서 다시 잘라 원본과 비교하는 검증을 포함하라. 문서상 기능과 실제 실행으로 확인한 결과를 구분해 기록하라. 현재 요청은 조사 자료 인계이며, 설치나 구현은 사용자의 후속 요청 범위에 맞춰 진행하라.
